Candidate arithmetic and exact meaning

Definition used

For an odd prime p, L_p is the smallest positive nonsquare x satisfying x mod 8 = 1 and a nonzero quadratic residue modulo every odd prime q <= p. Labels advance through primes: 379, 383, 389, 397. A qualifying number need not itself be prime.

Enumeration argument to inspect

This page is a proof sketch and review map, not a substitute for checking the frozen implementation. All arithmetic bounds refer to this specific campaign.

1. Unique representation

The moduli are coprime. For each x choose t_n = (-x M_p^-1) mod M_n, in [0, M_n). Then t_p = (x + t_n M_p)/M_n is an integer and x = t_p M_n - t_n M_p. This canonical choice is unique.

2. Sufficient outer bounds

first = ceil(lo / M_n)
end = floor((hi - 1 + (M_n - 1) M_p) / M_n) + 1

For lo <= x < hi and canonical t_n, these bounds contain every possible t_p. Batches partition [first, end) and split at M_p period boundaries. Reviewer: independently derive both floor/ceiling endpoints.

3. Correct residue sets

For q dividing M_p, require t_p in M_n^-1 QR(q). For q dividing M_n, require t_n in (-M_p)^-1 QR(q). Modulo 8, require t_n = (-M_p)^-1 mod 8. QR excludes zero. Verify the inverse signs; using unscaled QR sets would be wrong.

4. Complete focus enumeration

Each admissible residue is built from CRT contributions. Rings are split into two groups C and D. For each d, binary searches on sorted C select sums in a requested window, with wrap = 0 and 1. Because c,d are in [0,M), these two cases cover (c+d) mod M. Reviewer: check constants, empty groups, exact endpoints, period offsets, and injectivity.

REVIEW PACKET / 05

GPU exclusion and safety obligations

5. Every compatible pair reaches the predicate

The positive A window is sorted. With actual_a = min(A) and actual_b = max(A)+1, the negative B bounds are tightened as follows. An empty A batch is committed with zero candidates.

bnlo = max(0, floor((actual_a M_n - hi) / M_p) + 1)
bnhi = min(M_n, floor(((actual_b-1) M_n - lo) / M_p) + 1)

For each t_n in B, the kernel binary-searches the first A product at least t_n M_p + lo, then scans while that product is below t_n M_p + hi. Review off-by-one cases, period splits, and empty windows independently.

6. Exact arithmetic and all prime filters

Products and differences use two 64-bit limbs. Both focus moduli are below 2^63, so adding two reduced CRT contributions fits in 64 bits. In this campaign t_p is below 2^61 and t_n below 2^62; their products and additions stay far below 2^128. Review carry, borrow, unsigned comparisons, and all intermediate bounds.

The focus primes cover odd primes through 97. The match filters cover every remaining odd prime 101 through 379, with zero residues forbidden. V2 reconstructs the wide x and reduces it for the first four filters; legacy uses packed scaled A residues plus scaled negative B residues. Both versions must be reviewed because both contributed committed coverage.

7. Square rejection and finite buffers

The square test uses a floating-point square-root estimate followed by integer correction and exact wide multiplication. Review termination and r+1 safety for x <= 2 x 10^25. Confirm this rejects only true squares.

A/B capacity is 67,108,864 entries. Over-capacity generation must return overflow and retry a smaller uncommitted window. The survivor buffer holds 100,000 values; excess must stop before coverage is committed. Review atomic counts, synchronization, bounds, and crash behavior. No full GPU rerun or fault-injection campaign was performed for this packet.

8. Memory claim and implementation scope

This engine stores large half-sum arrays: positive [66,718,080, 1,940,400] and negative [66,774,240, 1,912,680], plus batch buffers. Do not describe its total working memory as only the sum of admissible residue counts. The initial mixed-radix terms and the production working arrays are different quantities.
